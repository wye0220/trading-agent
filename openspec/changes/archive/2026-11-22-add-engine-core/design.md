# Design

## Context

动机见 proposal.md。可用的输入：阶段 1 的 as-of 查询（`context.visible_bars` 等）和运行库；阶段 2 的 `StrategyProvider`、`OrderIntent`、`features.build_context`。

约束：Python 决定信号、风控、成交和盈亏；同一输入重跑不重复生成订单或结算；禁止回写早先的订单、信号、成交；不插值、不造成交；引擎不依赖任何特定策略的内部字段。

行情的粒度有两种：Databento 时段有 1 分钟线，Webull 时段（目前不可用）只有 5 分钟线。成交模型要在两种粒度上给出一致的规则。

## Goals / Non-Goals

**Goals:**

- 一套成交规则，`scan`、`replay`、影子运行共用。
- 每个成交都能说清：用了哪些行情、当时是否可见、先后是否确定。
- 一个与 PA 无关的模拟策略能跑通全流程。

**Non-Goals:**

- 不做部分成交、排队位置、盘口深度。固定 1 手的纸面单按触及即成交。
- 不做真实下单。
- 不评估策略好坏。

## Decisions

### 1. 范围只到 Prompt 3，分支 `phase-3-engine`

### 2. 四个时刻

对一根在 `T` 收盘的 5 分钟信号 K：

| 时刻 | 定义 |
| --- | --- |
| 信号 K 收盘 `T` | `bar_end_utc` |
| 数据可用 `A` | 这根 K（当时可见的 revision）的 `available_at_utc` |
| 决策／挂单激活 `t` | 引擎处理这根 K 的时刻。回放里取 `A`；盘中取实际运行时刻，不早于 `A` |
| 有效期截止 `X` | `T + ttl_bars × 周期`。`ttl_bars=1` 时是下一根 K 的收盘 |

- `t ≥ X` 时不再挂单：记一条 `MISSED_LATE_SIGNAL`，不生成订单。09:40 之后不补挂。
- 激活之前的触价不可用。
- 时钟只前进：每个运行（`run_id`）记一个水位，步进的决策时点早于水位时拒绝。

### 3. 行情的"子 K"与激活的关系

成交模型吃的是一串**子 K**：有 1 分钟线就用 1 分钟线，否则用 5 分钟线本身。对一张在 `t` 激活的订单，子 K `[s, e)`：

- `e ≤ t`：完全在激活之前，对这张订单不存在。
- `s ≥ t`：完全在激活之后，正常使用。
- `s < t < e`：**跨着激活时刻**。里面的触价无法确定在激活前还是后。处理：照常按规则成交，但给成交打 `AMBIGUOUS_ENTRY` 标记，单独统计。

为什么不选"跨着激活时刻的触价一律不成交"：只有 5 分钟线时，下一根 K 必然跨着激活时刻（激活在它开盘后几秒），那样所有订单都无法成交。提示词包自己的例子（"下一根开盘 5003 → 触发但未成交"）也把下一根的开盘当作可用事件。所以默认成交并标记；标记占比由阶段 5 的报告单列。

这条规则和事件顺序一起进成交模型的版本号。

### 4. 子 K 内的价格路径

只有开高低收时，已知的先后只有：开盘最先，收盘最后。规则按做多叙述，做空镜像。

**`STOP_LIMIT_NEXT_BAR`**（触发价 `P`，限价 `L ≥ P`）：

| 情形 | 结果 |
| --- | --- |
| 开盘 ≥ `P` 且开盘 ≤ `L` | 触发并在开盘价成交 |
| 开盘 > `L` | 触发但未成交（`TRIGGERED`）。同一子 K 的最低价 ≤ `L` 时，说明之后回落到了限价，按 `L` 成交；否则带着 `TRIGGERED` 状态进入后面的子 K |
| 开盘 < `P` 且最高价 ≥ `P` | 盘中触发，按 `min(P + 入场滑点, L)` 成交 |
| 最高价 < `P` | 不触发 |
| 已 `TRIGGERED`，后面的子 K 最低价 ≤ `L` | 开盘 ≤ `L` 按开盘成交，否则按 `L` 成交 |
| 到截止时刻仍未成交 | `EXPIRED` |

任何情况下成交价都不高于 `L`。

**`MARKET_NEXT_OPEN`**：在激活后第一个可用的开盘价成交。有 1 分钟线时是第一根起始时刻 ≥ `t` 的子 K 的开盘；只有跨着激活时刻的子 K 可用时，用它的开盘并标 `AMBIGUOUS_ENTRY`。加入场滑点。

**`LIMIT_RETRACE`**（限价 `L`，价格回落到它才买）：有效期内某根子 K 的最低价 ≤ `L` 时按 `L` 成交，不给价格改善。

**成交之后**，保护止损和目标立即生效：

| 情形（同一子 K 或之后的子 K） | 结果 |
| --- | --- |
| 开盘已越过止损（跳空） | 按开盘价加不利滑点出场，标 `GAP_THROUGH_STOP` |
| 只触及止损 | 按止损价加不利滑点出场 |
| 只触及目标，且触及一定在入场之后 | 按目标价出场 |
| 止损和目标都可能触及 | 止损优先，标 `AMBIGUOUS_BAR` |
| **入场当根**触及止损（含"跳空触发、回落成交、同根穿损"） | 止损优先，标 `AMBIGUOUS_BAR` |
| 入场当根触及目标，但无法确定在入场之后（回落成交的情形） | 不算目标成交，标 `AMBIGUOUS_PATH`，仓位带入下一根 |

"入场当根触及目标"何时算确定：从下方盘中触发（开盘 < `P`）或在开盘价成交时，高于入场价的价格必然出现在入场之后，可以算。回落到限价才成交时，最高价可能出现在成交之前，不能算。

目标的触及口径：价格到达目标价即成交。阶段 5 另报"穿价 1 tick 才成交"的敏感性。

### 5. 目标定价

成交后把三种目标描述换成价格（做多）：

- `ABSOLUTE_PRICE_TICKS`：就是它。
- `OFFSET_FROM_FILL_TICKS`：成交价 + 数值。
- `INITIAL_RISK_MULTIPLE`：成交价 +（成交价 − 止损价）× 倍数，向不利方向取整到整数 tick（做多向上）。

目标价不在成交价的顺方向一侧时（例如止损已被成交价越过），订单成交后立即按 `INVALID_AFTER_FILL` 以止损规则处理，并打标记。

### 6. 截止强平、反手、缺数据

- **截止时刻** = RTH 收盘前 5 分钟（常规日 15:55 ET，提前收盘日相应提前）。到点：先撤未成交的入场单，拦截新仓，再把持仓按截止时刻起第一个可用价格加不利滑点平掉，标 `FORCED_FLAT`。截止后没有行情时记 `UNABLE_TO_FLATTEN`，仓位标为无法定价，等第一个有效价格再平。
- **反手**：同 scope 不双向持仓。持仓期间一张反向订单成交时，在同一个模型价格上原子地平掉旧仓、开出新仓，各记各的费用，旧仓退出原因 `REVERSAL`。反向订单没成交时旧仓照常管理。
- **缺数据**：有效期内没有子 K 的时段不产生任何成交。订单到期按 `EXPIRED`，并标 `DATA_GAP_IN_WINDOW`。持仓期间缺数据，仓位标 `UNPRICEABLE`，数据恢复后从第一个可用子 K 继续。
- **换月**：订单和仓位绑定实际合约，只吃该合约的子 K。日内强平保证不跨换月。

### 7. 逐步运行器

`engine.step(settings, con, run, strategy, as_of)` 一步做完：

1. 取水位之后、`as_of` 时已可见的子 K，逐根喂给成交模型，推进挂单和持仓。
2. 取 `as_of` 时可见的 5 分钟线，组装 `FeatureContext`（含本交易日已完结的纸面交易），调用 `strategy.on_bar`。
3. 若 `SETUP_VALID`：在同一事务里重读冻结状态和数据阻止状态；通过则按风控结果生成订单（`ARMED`），否则记拦截原因。
4. 写 `scan_events`、策略状态、水位。

一步在一个事务里提交。同一个 `(run_id, 信号 K)` 重跑是空操作，返回已存的结果。订单和成交的 ID 由 `run_id`、`setup_id` 等确定性生成。

`engine.replay(...)` 就是按 K 线收盘时刻依次调用 `step`。阶段 5 在它上面加报告。

*两个循环的隔离*：收线主循环（`step`）和异步中断（人工 `plan`、紧急 `freeze`、行情断流）都通过事务加 `version` 乐观锁写状态。`step` 在提交订单前重读冻结状态，所以"冻结与入场同刻"时冻结胜出。

### 8. 风控

**每手计划风险** = 止损 tick 数 × tick 价值 + 每手往返费用 + 滑点预算。费用配置成"每边"或"往返"二选一。已经计入成交价的滑点不再算进费用。

**两个风险域**：

| | 纸面 | 真实账户 |
| --- | --- | --- |
| 键 | scope、`run_id`、交易日 | `account_id`、交易日 |
| 手数 | 固定 1 手 | `floor(单笔预算 ÷ 每手风险)`，再受最大手数和当日剩余风险约束 |
| 预算门禁 | 不经过 | 经过。最少 1 手仍超预算 → 0 手，`BLOCKED`，`MIN_SIZE_OVER_BUDGET` |
| 两次止损 | 策略自己的纪律（阶段 2） | 账户级，跨所有策略共享；换策略不解除 |
| 日损 | 只记账，不拦 | 到限后拦同一账户的新入场，存量按原规则管理 |

真实账户一侧，本阶段提供纯函数 `check_manual_plan(...)` 和带事务的 `reserve(...)`（核验与预留在同一事务里），阶段 4 的 `plan` 调用它们。账户状态缺失或过期时返回 `BLOCKED`、`RISK_UNKNOWN_OR_STALE`。预算未批准时返回 `BUDGET_NOT_APPROVED`。

**R 的计量**：每笔交易同时记两个 R：按预登记的固定研究风险单位 `$X` 计的（主口径，A/B 一致），和按该笔初始风险归一化的（辅助）。`$X` 没配置时只有后者，并标 `RESEARCH_RISK_UNIT_NOT_SET`。

**费用没配置时**：按 0 计，并在每笔结果上标 `FEES_NOT_CONFIGURED`。不猜一个数。

### 9. 版本绑定

`versions.current(scope)` 返回版本元组：`strategy_family`、`strategy_version`、`risk_version`、`prompt_version`、`memory_version`、`engine_version`、`model_id`。

- 发布库里该 scope 有 active 指针时，以它的清单为准。
- 没有时（现在的情况），由注册表里的策略版本、风控配置的内容摘要和引擎版本现场组成，并带 `release_id = UNRELEASED`。
- 每一步开始时加载一次。新订单记下当时的元组；已排队的订单和持仓继续用自己记下的那个。

`engine_version` = 成交模型版本 + 事件顺序规则版本。改成交规则必须改它。

### 10. 上下文构建器与 schema

- `build_scan_context(...)` 只放：scope、时刻、信号状态、订单意图的数值、决策元数据的结构和证据、当前纸面仓位摘要、参考价位。**不放原始 K 线序列。**
- 每类调用有 token 预算（按字符数保守估算）。超预算时按固定顺序裁掉证据里的次要部分；裁到底仍超则报错，不静默截断。
- `schemas/` 下六个 JSON Schema：`ScanExplanation`、`PretradeCheck`、`SessionReview`、`Candidate`、`MemoryCandidate`、`ReleaseReview`。字段按提示词包各阶段的描述定最小集，`additionalProperties: false`。
- `validate_output(kind, obj)`：不合格的输出丢弃，记一条告警，不影响确定性流程。
- 解释请求写进队列表，带原快照 ID。模型不可用时留在队列里重试，重试用的仍是原快照。本阶段不调用模型，只提供入队、取出、标记完成或失败的函数。

### 11. 存储（migration 0002）

| 表或列 | 用途 |
| --- | --- |
| `engine_runs` | 每个运行的 scope、模式、风险域、水位、当前策略状态、`version` |
| `paper_positions` | 纸面仓位：方向、成交价、止损、目标、状态、标记、绑定的版本元组、`version` |
| `paper_trades` | 已完结的纸面交易：盈亏（tick 和美元）、两种 R、退出原因、标记 |
| `explanation_requests` | 解释请求队列 |
| `account_risk_days` | 真实账户按交易日的已实现亏损、预留、止损次数、是否停手、`version` |
| `risk_reservations` | 人工计划的风险预留 |
| `paper_orders` 加列 | 激活时刻、截止时刻、信号 K 时刻、触发价、限价、止损、目标描述、标记 |

### 12. 测试向量

`tests/vectors/fills/*.yaml`：订单、激活时刻、一串子 K、期望的事件序列（状态、成交价、退出原因、标记）。沿用阶段 2 的做法，每个向量正向和镜像各跑一遍。

## Risks / Trade-offs

- **`AMBIGUOUS_ENTRY` 默认成交并标记，是我的选择** → 写入假设；提示词包对入场歧义给了"记 MISSED 或 AMBIGUOUS_ENTRY"两种说法。规则版本化，改起来只动一处。
- **回放里激活时刻取"收盘 + 5 秒"** → 第一根 1 分钟线总是跨着激活时刻，在那一分钟内触发的入场都会带 `AMBIGUOUS_ENTRY`。这如实反映了历史数据没有到达时刻这件事。
- **触及即成交偏乐观** → 阶段 5 报穿价 1 tick 的敏感性。
- **费用和限额没填** → 标记而不是猜；人工预算在填写并批准之前一律不放行。
- **本阶段之后契约冻结** → 冻结前由用户验收；冻结后改表要走 migration。

## Open Questions

- 费用、滑点预算、研究风险单位、账户限额的具体数值，由用户填进 `config/risk.yaml`。不影响本阶段的实现和测试（测试自带数值）。
